### C.2 未实测（如实标注）

- **QPS / P95 / P99（业务端点）**：未做压测。原因：业务端点真实打引擎，压测会直接触发百度风控并污染当前出口 IP；应在隔离出口 + 代理池环境做。
- **长跑内存**：未做 4 小时稳定测试。已有 `app.idle_ttl` 空闲回收与 `max_processes` 上限，但没有实测曲线。
- **数据库高并发**：bbolt 是单写者，写入集中在用量账本；未做写放大测试。当前用量保留 30 天 + 日聚合，规模假设未验证。

### C.3 瓶颈判断（基于代码与实测）

1. **出口 IP 是首要瓶颈**，不是 CPU：百度 5 次/分钟 ≈ 300 条/小时/IP。要提高吞吐只能加出口（代理池）或走站长平台 API。
2. **浏览器进程池**（`app.max_processes`，默认 4）决定并发上限；1.4GB 机器上 2 个为宜。
3. **bbolt 单写者**：批量任务每条结果 append 到 JSONL（不是 bbolt），DB 只在提交/进度落盘时写，压力可控。

## E. 核心业务（百度收录查询）专项

### E.1 链路

`POST/GET /v1/index/check` → 参数校验（去重、绝对 URL、≤5000）→ 引擎选择 → 单元调度（每引擎串行 + 令牌桶）→ 百度：抓目标页 `<title>`（4s 超时，SSRF 防护）→ 用标题检索 → 前 10 条 organic 中找同站 + 标题相似度 ≥0.72 → 得出 `indexed/match`。>20 条改走任务队列（同一判定逻辑）。

### E.2 实测结果

| 用例 | 结果 |
| --- | --- |
| 已收录 URL（2 条） | `indexed=true, match=exact, total_results=8~10` |
| 未收录 URL（2 条） | `indexed=false, match=none` |
| 早前判为未收录、1 小时后复核（4 条） | 全部 `indexed=true, match=exact` → 判定能跟上真实索引变化 |
| 767 条历史样本 | 41.7% 收录；判 true 的标题相似度最小 0.724、中位 1.000（阈值有效，无低分混过） |
| 近 132 条（当天发布） | 22.0% 收录，符合"新文章未收录"预期 |
| 批量 30 条 | 367 秒跑完，0 失败，ETA 准确 |
| CSV 导出 | UTF-8 BOM，Excel 直接打开 |

### E.3 准确性边界（必须对用户讲清）

1. `indexed=true` 是"搜索引擎可检索"，**不是**官方收录状态。
2. 结论随时间变化（小时级）；接口不缓存，建议 24–72 小时复查。
3. 已知漏判：标题被改写、转载压过原站、命中在前 10 条之外。
4. 已把上述口径写入 `docs/API.md`（本次修复 F-15）。
