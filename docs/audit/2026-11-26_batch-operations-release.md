# 2026-11-26 批量任务与上线验收

## 范围与边界

本轮覆盖批量收录任务、定时巡检、结果变化通知、资源监控和本机部署。验收目标是 Windows 本机 `127.0.0.1:7000`；没有向 `radar.ydsdoa.cn` 部署。该正式域名目前响应的是资讯雷达系统，不是本仓库服务。

## 实施内容

- 批量任务支持粘贴/CSV 导入、输入去重与预检、分页结果、流式 CSV、进度和失败重试。
- 管理控制台任务按用户隔离；REST、MCP 和控制台提交共享账本预留、幂等和启动对账。
- 每日/每周计划持久化在平台设置存储中，新建默认暂停；到期密钥或配额问题会暂停计划。
- 计划资源上限为全局 100 个、每用户 20 个、累计 10000 个 URL；单 URL 最长 2048 字节。
- 定时计划保存基线；有效收录结论变化或任务失败时产生可确认的站内通知，通知存储有硬上限。
- 管理总览展示 Go 堆、对象数、goroutine、数据盘容量和阈值状态。终态任务释放内存中的 URL 清单，终态任务驻留记录最多 500 个。
- 任务结果按页读取；任务历史保留默认为长期，配置正整数后会在启动时和每 12 小时清理到期终态任务。清理预览只读。
- 复审移除了无效的 `schedule_dir` 配置；批量/定时任务密钥选择器过滤停用或过期密钥，修复了计划密钥重复显示和提交时错误复用批量密钥的问题。

## Windows 本机部署与浏览器验收

- 部署脚本备份了原 exe 和 web 静态资源；原配置及数据目录保留。健康接口返回 `healthy`，存储类型为 bbolt，监听地址为 `127.0.0.1:7000`。
- 最新本机 exe 与验收候选文件 SHA-256 一致；部署目录中的 bbolt 数据库约 128 KiB，审计日志约 15 KiB。
- 在本机安装的 Chrome 与 Edge 中以 1280×900 和 390×844 视口检查批量/定时任务表单和资源卡片；页面无异常，滚动宽度不超过视口宽度。
- 用隔离的 Playwright 网络 mock 验证密钥选项：过期密钥不出现；计划下拉选中的 key ID 原样提交；选项无重复。mock 没有写入持久数据。

## 内存与清理

在最终服务进程树上采样约 3 分钟，共 17 个有效样本：工作集 29.1–30.3 MiB，私有内存 53.5–54.5 MiB。测试期间主要是管理控制台浏览器验收；未对搜索引擎进行批量压测。读数稳定，但这只是低负载短时基线，不能证明生产高并发或长期运行时不存在内存增长。

当前本机配置中日志滚动保留为 30 天，用量账本保留 30 天；服务通过启动、轮转和 12 小时周期清理过期日志。`index_jobs.retention_days` 未配置，采用默认 0，即任务文件不会自动删除。任务数据增长属于磁盘保留问题，不等同于常驻 Go 堆增长。由于启用任务保留策略会永久删除旧任务历史，本轮没有替用户设置保留期限。

Go 官方诊断建议结合 `runtime.ReadMemStats`、goroutine 统计和 heap profile 分析内存；本轮同时看了 Go 堆指标和 Windows 工作集/私有内存，但没有开放公网 pprof。[Go Diagnostics](https://go.dev/doc/diagnostics) 指出运行时统计可辅助发现内存和 goroutine 泄漏，精确 profile 采集可能干扰其他诊断。日志轮转和保留也按 [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 的资源耗尽与保留原则复核。
