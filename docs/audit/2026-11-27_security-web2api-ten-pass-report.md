# web2api 十轮安全复审

**范围**为基线 `8d85b10` 上的当前 Windows 工作树、部署示例和本机回环实例。证据来自本轮源码阅读、现有测试重跑、二进制重构建和本机 HTTP 响应。四项发现需要处理，其中调试路由风险取决于启用与入口暴露状态。本轮未探测公网、未开启调试路由，也未修改应用或部署配置。

## 发现

- **F1 · 中 · 并发改密可能留下新会话。** 登录先读取用户及旧密码哈希，再取得认证锁。若密码轮换在两步之间完成，等待中的登录可能继续使用旧快照验证，同时取得改密后的令牌版本并创建新会话。需要旧密码和并发改密窗口。修复时在同一个认证锁内读取最新凭据及版本，并将会话签发纳入同一边界。[登录读取与锁](../../platform/handlers_admin.go#L167) · [令牌版本与会话](../../platform/handlers_admin.go#L200) · [改密写入](../../platform/handlers_admin.go#L295)
- **F2 · 高，需启用且可达 · 调试浏览器缺少访问与出站限制。** 调试路由直接注册，未挂搜索数据面的鉴权。自定义目标仅检查 HTTP/HTTPS 和主机是否存在，浏览器导航后会把提取内容放入报告。取决于服务的网络可达范围，可能访问并返回内部页面内容。将调试入口限制给授权管理员，并约束浏览器出站与重定向。[路由](../../core/server.go#L305) · [URL 校验](../../core/fpcheck/detectors/custom.go#L128) · [浏览器执行](../../core/fpcheck/runner.go#L34)
- **F3 · 低 · MCP URL 错误仍可能被配额响应掩盖。** 工具解析只验证输入为非空字符串，收录逻辑稍后才检查协议和目标格式。余额不足时，后端 URL 错误可能先表现为配额 `429`。应在预留之前复用执行端的 URL 校验。[工具校验](../../mcp/tools.go#L290) · [URL 值校验](../../core/server.go#L1418)
- **F4 · 低 · REST 和 MCP 异步提交各消耗两次限流额度。** API Key 中间件先扣一次，公共任务入队又对同一 Key 扣一次。限流启用时更早出现 `429`，影响吞吐量。每日用量由另一套事务控制。应让同一次外部提交只经过一次 Key 限流，同时保留控制台和计划任务入口自身的限制。[REST](../../platform/middleware.go#L174) · [MCP](../../platform/security.go#L419) · [入队](../../platform/job_submit.go#L128)

## 校验与复盘

- `go test -count=1 ./...`、`go vet ./...` 和 `git diff --check` 通过。重构建 SHA-256 为 `DB2C36FFCB9AE442B899FDA1DA174601AEA40FCD675F8C119809E400B024FF09`。
- F1 至 F4 来自源码路径核对。本轮未运行竞态复现，也未通过调试浏览器访问内部地址。现有测试通过仅支持其覆盖的路径。
- 历史管理员修复解决了启动时的凭据识别，运行期仍要单独验证改密并发。MCP 的类型校验、后端值校验及入队不是同一阶段，逐阶段比对才定位了校验遗漏和重复限速。部署文档和本机默认值只能说明预期行为与当前本机状态，公网配置需要独立取证。

## 修复与复验

| 编号 | 处理及结果 |
| --- | --- |
| F1 | 登录在认证锁内读取凭据，与改密、管理员重置及会话签发共用同一把锁。凭据操作和旧令牌失效回归通过。 |
| F2 | 移除 HTTP 调试路由，指纹诊断迁到本机 `web2api fingerprint-check`。真机运行本机诊断成功，部署后旧 HTTP 路径返回 404。 |
| F3 | MCP 同步收录在预留前复用收录执行端的 URL 校验。配额耗尽时非法 URL 仍返回 `-32602`，回归测试通过。 |
| F4 | REST 和 MCP 的异步提交只消耗一个 Key 限流令牌。回归覆盖两条入口，并验证每日计费用量与任务提交数相符。 |

全量 Go 测试、`go vet` 和差异检查通过。修复版已部署至本机 `127.0.0.1:7000`，健康、就绪和管理员登录正常，匿名管理请求返回 401。公网部署未变更。

## 改密存储失败复核

后续只读复核发现，改密与会话失效原先各自落盘，写入失败时可能留下部分更新。自助改密和管理员重置现已将用户密码、适用的全局令牌版本、会话撤销及自助改密的新会话一起提交。bbolt 使用同一写事务，JSON 回退存储一次替换文件并在出错时还原内存状态。两种后端通过了故障注入回归，HTTP 回归也确认失败时不会签发新的客户端凭据。
